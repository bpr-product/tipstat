## Approved design decisions
- Official service first; HUSH is design input only. Prototype-derived `engineering_reference/` and `stage_prompts/` are excluded via `.git/info/exclude`; disclose the prototype in `MEMORY.md`.
- Storage: SQLite + FTS5 at `$MEMORY_DB` or `<tempdir>/memory.db`; no projects; `/reset` drops and recreates tables.
- Remember: chat and free-text events get one extraction call with up to 6 related active facts; structured events (calendar/task/reminder/contact) are applied in code, no model call. Inbound/assistant text can only become `attribution='other'` facts (code-enforced).
- Update: model returns `replaces` (id from the supplied related list); accepted only if supplied and still active, then old becomes `superseded` (with `ended_ts`), new points to it. Otherwise both stay active. Cancellation is a new CURRENT fact.
- Ask (stage 04): call 1 = keyword expansion (small; skipped if nothing stored; failure falls back to lexical only), then BM25 over all ages, active facts + predecessor chains + sources; call 2 = answer under ~3.3k est. tokens; evidence = only validated citations (supplied items); no candidates = abstain with no answer call. Event sources already quoted by a supplied fact are not sent twice. Candidates, supplied items and cited items are separate in `trace`.
- Forget (stage 05) - DEVIATION from HUSH preview/confirm UI: the official API has no confirmation channel, so the user's own message is the instruction. Only chat user lines or user-sent events can trigger it (inbound/assistant never). Flow: broad regex hint (no deletion by itself) -> candidates by search (all versions + sources, request's own source excluded) -> 1 model call proposes `fact_ids`/`source_ids` (only ids it was shown) -> deterministic plan: whole version chain, every source evidencing a removed fact, facts supported only by removed sources, and anything still stored whose text contains a removed fact's quote (>=12 chars) -> erase facts/evidence/FTS/sources in one transaction, `PRAGMA secure_delete=ON`, FTS optimize + VACUUM -> verify (no dangling links, no phrase left) -> payload-free `forget_log` row. The request's own text is scrubbed (row kept so replay is a no-op); facts extracted from the request that share value/quote words with erased content are dropped, other facts from it are kept. Budget: extraction + one forget call = 2 calls/message.
- /act (stage 06; no HUSH stage covers it, it is an official requirement): context = standing RULE facts + relevant current facts + OUTDATED versions labelled "do not act on" + up to 3 source snippets (1 keyword-expansion call, reused from Ask). Tool loop uses all 29 world tools over plain HTTP, only tools the world listed; <= 12 model calls total, per-call cap 6,800 est. tokens (older tool results trimmed first), job cap 52,000 est. tokens, 80 s; the last allowed call forces `tool_choice=none`; if tools are unreachable nothing is changed and the reply says so. Rules (look before write, update not duplicate, resolve people, honor flights/standing rules/cancellations, decline vs cancel, no extra actions) are in the system prompt, not enforced in code. /act never writes memory.
- UI (stage 06) - DEVIATIONS from HUSH Stage 06/ch.13-14: plain HTML/JS/CSS with the Marginalia tokens (dark/light, serif answers, evidence drawer, dashed abstention rule), no React/Vite build; no project selection or isolation demo (no projects exist); no update/forget review dialogs (the official API has no review step; Forget and corrections happen by chatting, and the Memories page shows current/history/receipts); `server.py` untouched, so the UI is a separate process (`python frontend/serve.py`) and the Memories page reads the SQLite file directly (works only when the service runs on the same machine with the same MEMORY_DB, not in Docker). Pages: Chat (Tell/Ask/Do), Memories (+ forget receipts), System (health, reset with confirmation). frontend-design skill was not invoked (approved tokens used as given).
- Dates: relative dates resolved at write time against the message ts; invalid becomes null.
- Deviations from HUSH: no workspace/project scoping, no "Remember" composer, no review UI, no embeddings (keyword expansion instead).

## Second manual review: findings, causes, fixes (tests: `tests/test_review2.py`, 12)
1. Forgotten info visible in old receipts (CONFIRMED, fixed). Cause: redaction compared only text/terms; a receipt label such as "allergy: shellfish" joins fields, so its word pair was never in the erased set, and the single word lived on in another fact. Fix: Tell receipts and cited answers now carry `fact_refs`; a message referencing an erased fact id is redacted, and so is the other half of the turn (same request id). Visible text only is compared (string values), so metadata cannot match.
2. Related memories survive a broader Forget (CONFIRMED, fixed for explicit broad requests). Cause: closure needs shared rare words of 5+ letters or a model pick, so facts that only share a short name survived. Fix: a request containing everything/all/any/whole/entire/every adds every fact and source that names a capitalised name from the request. A narrow request is unchanged (test).
